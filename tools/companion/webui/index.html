Help

The things that go wrong most often, and what to do about them.

Cloud sign-in fails

  • HTTP 403 with "CSRF". You are on an old build. Bambu added a CSRF check to the 2FA step in mid-2026. Grab the current Companion Tool.
  • HTTP 403 otherwise. Cloudflare fronts Bambu's login servers and turns away anything that doesn't look like a browser. From source, run pip install -U curl_cffi. From the exe, download the current build - the library is baked in.
  • Wrong region. An account created in China cannot sign in against the US/EU servers, and the other way round.
  • Still blocked. Use LAN mode instead, or paste a token from the Bambu Handy app into the device's own web UI.

The device isn't found

  • Same network. The scan only covers the subnet this computer is on. A guest VLAN or a second WiFi band with client isolation will hide the device.
  • Still booting. Give it 20 seconds after power-on before scanning.
  • Type the IP instead. It is shown on the device screen after WiFi setup.

Diagnostic results

  • TCP fails. LAN mode: wrong IP, different subnet, or the printer is off. Cloud mode: no internet or DNS.
  • TCP or TLS times out while the printer is definitely online. Its local MQTT slots are full. Bambu printers accept only about 3 local clients at once, counting every BambuHelper device, Panda Touch, Home Assistant and Bambu Studio session in LAN mode. Once they are all taken the printer either stops answering on port 8883 or accepts the TCP connection and then stalls in the handshake - both look like a printer that is switched off. Disconnect one client, or switch to Cloud mode: cloud connections do not use the printer's local slots.
  • MQTT rc=4 or rc=5. Bad credentials. LAN: re-check the Access Code. Cloud: the token has expired - they last about three months.
  • Connected but no messages. Almost always a serial number mismatch. Bambu's MQTT topics are case-sensitive and the serial must be uppercase.

Privacy

  • Your password is never stored. It is used for the login request and then dropped - not written to disk, not kept in memory after sign-in.
  • The access token lives in memory for as long as this app is open, so it can be pushed to your device. Quitting discards it.
  • This app talks to Bambu Lab's login servers, and your BambuHelper on the local network. Nothing else.
